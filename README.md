# Supermarket Sales Analysis

An interactive Streamlit dashboard and a companion PDF report for exploring
supermarket transaction data. The dashboard covers sales performance, data
quality, products and categories, branches and cities, customer segments,
payment methods, and sales trends.

## Project structure

```text
.
├── analysis.py                         # Streamlit dashboard entry point
├── data/
│   └── raw/
│       └── supermarket_sales_500_rows.csv.xlsx
├── reports/
│   ├── legacy/
│   │   └── Supermarket_Sales_Report.docx
│   └── Supermarket_Sales_Report.pdf    # Generated by the report script
├── scripts/
│   └── generate_report_pdf.py
├── requirements.txt
└── README.md
```

Keep source data in `data/raw/`, generated or reviewed deliverables in
`reports/`, and one-off project utilities in `scripts/`. Do not put temporary
files, virtual environments, or credentials in source control.

## Requirements

- Python 3.11 or newer
- Dependencies listed in `requirements.txt`

## Setup

From the project root, create and activate a virtual environment, then install
the project dependencies:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks environment activation, use the virtual environment's
Python executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Run the dashboard

```powershell
streamlit run analysis.py
```

The dashboard reads `data/raw/supermarket_sales_500_rows.csv.xlsx` relative to
the project files, so it can be launched from the project root without changing
the working directory.

The workbook's `Table 1` sheet reads as 497 rows because its first three
transaction records are embedded in the header cells. The loader reconstructs
those records, producing 500 transactions, then standardizes column names,
converts data types, and recalculates sales from quantity and unit price before
displaying the dashboard.

## Generate the PDF report

```powershell
python scripts/generate_report_pdf.py
```

The PDF is written to `reports/Supermarket_Sales_Report.pdf`. The current generator builds a curated report and does not load the workbook
itself. The existing Word report and PDF-generator content describe 497
transactions, while the dashboard reconstructs 500; treat those reports as
legacy snapshots and reconcile all figures against the cleaned dashboard data
before publishing them.

## Data and report handling

- Treat the workbook in `data/raw/` as the original input. Keep cleaned or
  transformed data separate rather than overwriting the source.
- Review the dashboard's data-quality tab after replacing or updating the
  workbook.
- Confirm the dataset's redistribution terms before publishing the repository
  publicly.
- Generated PDFs and temporary Excel lock files are excluded by `.gitignore`.

## Dependencies

The pinned packages support Excel ingestion (`pandas`, `openpyxl`), dashboard
rendering (`streamlit`, `plotly`), and PDF generation (`reportlab`). `numpy` is
also pinned in `requirements.txt`.
